# Architecture

`dsh-pixel-studio` is split into a Node host half and a browser client half,
following the standard DeepSeek Harness plugin package layout.

```text
package.json
  main       → lib/index.js
  exports["./client"] → lib/client.js
  dsh.client → { platform: "web", inject: ["@deepseek-ai/dsh-client-ui-tool"] }
```

## Host half

The host plugin registers:

- a `pixel-studio:craft` system-prompt section;
- two tools, `pixel_art` and `pixel_animation`.

Tool execution is deterministic:

1. Validate dimensions, grids, palettes, frame timings and output limits.
2. Resolve the palette, legend or template roles.
3. Compose layers with source-over alpha.
4. Apply effects (outline, shadow, background).
5. Generate motion frames or use explicit frames.
6. Encode PNG, GIF, spritesheet, atlas JSON, OYPX and a manifest.
7. Build compact inline canvas metadata.
8. Return file paths, craft report and inline canvas in the structured output.

The presentation metadata is a separate projection of that result:

```text
{
  canvas: {
    available: true,
    width, height,
    colors: ["#RRGGBBAA", ...],
    frames: [{ rows: ["...", ...], durationMs, label }]
  },
  imagePath, gifPath, sheetPath, oypxPath, ...
}
```

### Why a custom inline format?

- One character per pixel is smaller than JSON pixel objects or base64 RGBA.
- The host can produce it without canvas.
- The client can decode it into `ImageData` synchronously.
- The format is bounded: ≤131,072 pixels and ≤64 colours. Larger art returns
  `available: false` and the client renders a compact open-files fallback.

## Client half

`lib/client.js` is a hand-written client module:

```js
window.__ModuleLoader__.load({
  id: "dsh-pixel-studio",
  factory(require) { ... return { apply, inject }; }
});
```

It requires only the `react` runtime supplied by DSH. During materialization it
injects scoped CSS. `apply(ctx)` registers a keyed `tool.call.toolview` entry
for both tool names.

The view:

- decodes each frame into an offscreen canvas via `createImageData`;
- draws the current frame with `imageSmoothingEnabled = false`;
- optionally draws the previous frame at low alpha (onion skin);
- advances frames with a `setTimeout` chain, paused for reduced motion;
- exposes zoom, grid, background and file-open actions;
- collapses without losing the active frame.

No image request, data URL, iframe or network access is needed.

## Security boundaries

- The host owns all file writes. The client receives only display data and
  file paths.
- Inline canvas data is generated by the host and bounded; the client never
  evaluates HTML from artwork names or palette values (React escapes text).
- The client uses `openFile` callbacks from DSH rather than constructing raw
  resource URLs.
- No third-party runtime dependencies are bundled. The GIF/PNG/OYPX encoders
  are local implementations.

## Compatibility

- DSH 0.2.x, client platform `web`.
- Node 20+ for host execution and tests.
- OYPX target: version 2, direct `#RRGGBBAA` row RLE, current oy-pixel parser.
- GIF: GIF89a, global 256-colour table, transparent index 0, disposal 2.

## Test strategy

`node:test` covers:

- colour parsing and palette ramps;
- grid, layer and transform behavior;
- PNG/GIF signatures and byte-level structure;
- OYPX row-width and direct-colour tokens;
- inline canvas encoding and budget fallback;
- craft checks;
- DSH tool/section registration;
- client bundle registration and a real-React render check (optional local
  verification, not part of the public test suite).
